# VACV-SI: Предсказание индекса селективности ингибиторов вируса вакцинии

**Результат на Kaggle (публичный лидерборд):**  
- v1: **1 661 893.99**  
- v2: **1 536 206.96** (улучшение ~125 тыс. / 7.6%)

Репозиторий содержит полное воспроизводимое решение задачи предсказания Selectivity Index (SI) для соединений против вируса вакцинии. Включает сбор данных из открытых источников, извлечение молекулярных признаков, ансамбль моделей и постобработку на основе структурных аналогов.

## 1. Подходы и модели

### Целевая переменная
Предсказываем **SI = CC50 / IC50** (индекс селективности) соединений против вируса вакцинии.

Метрика — **MSE**. Распределение сильно перекошено: одно соединение в обучении с SI ≈ 36 067 даёт около 95% всей суммы квадратов ошибок. Поэтому при выборе моделей используется **обрезанная MSE** (99-й / 99.7-й процентиль), чтобы несколько выбросов не доминировали.

### Признаки
- **Morgan-отпечатки** (счётчики, радиус 2, 2048 бит) — основной признак
- 2D-дескрипторы RDKit
- MACCS-ключи
- Контекст эксперимента: клеточная линия, штамм вируса (one-hot / target encoding)

Обычные Morgan-отпечатки **не учитывают хиральность**. Это оказалось важно: три тестовых соединения являются эпимерами главных рекордсменов обучающей выборки.

### Модели (ансамбль)
1. ExtraTreesRegressor
2. RandomForestRegressor
3. HistGradientBoostingRegressor
4. SVR с ядром Танимото (по Morgan-отпечаткам)

Итоговый прогноз — взвешенное среднее. К нему применяется глобальный масштабный коэффициент `c`, который оптимизируется на кросс-валидации.

### Важные решения
- **Нет утечки меток теста.** Колонки `CC50_uM` и `IC50_uM_VACV` из `test.csv` никогда не используются (защита проверяется юнит-тестами).
- Внешние данные (ChEMBL/PubChem) фильтруются: молекулы, которые есть в тестовом наборе соревнования, удаляются по умолчанию (можно отключить флагом `--keep-test-overlap`).
- Все генераторы случайности зафиксированы → побайтово одинаковые результаты при повторном запуске (проверено в режиме без RDKit).

## 2. Эксперименты и что удалось проверить

Процесс разработки (восстановлен по рабочему логу):

### Этап 0 — Каркас и офлайн-режим
- Полный набор тестов (сначала 18, потом 26–32).
- Запасной набор признаков без RDKit, чтобы можно было проверять пайплайн на машинах без химических библиотек.
- Офлайн-режим `run_all.sh`, который пропускает сетевые вызовы.

### Этап 1 — Устойчивость сбора данных
Скачивание из ChEMBL иногда зависало на очень больших документах (сотни тысяч активностей). Исправления:
- Фильтр по типам активностей (`IC50`, `EC50`, `CC50`, `CD50`, `TC50`, `SI`).
- Таймаут на документ (300 с) и лимит размера (50 000 активностей).
- Автоматический пропуск + запись в `skipped_docs.csv`.
- Полный кэш HTTP-ответов в `data/external/cache/`.
- Промежуточные сохранения каждые 20 документов.
- Корректная обработка Ctrl+C.

Коллектор PubChem получил аналогичные ограничения.

### Этап 2 — Базовая модель (v1)
- Кросс-валидация по каркасам.
- Масштабный коэффициент `c` ограничен сверху значением 3.
- Ансамбль из четырёх моделей, перечисленных выше.
- Публичный лидерборд: **1 661 893.99**.

### Этап 3 — Анализ ошибки
- ~89% квадрата ошибки (без главного выброса) приходится всего на 13 соединений с SI ≥ 500.
- Три тестовых соединения (`7e-as-515`, `8b-as-556`, `7l-as-529`) — эпимеры главных рекордсменов обучения (SI 36 067, 2 325, 992).
- Стандартные Morgan-отпечатки не различают хиральность → модель видит их как те же объекты, что и высокоактивные обучающие примеры.
- Случайная CV (вместо CV по каркасам) даёт более реалистичную оценку обобщения, потому что сходство «тест → ближайший сосед в train» почти совпадает с «train → train».

### Этап 4 — Улучшения v2
Реализованы в отдельном скрипте `train_v2.py`, который пишет только в `outputs_v2/` (артефакты v1 не затрагиваются).

Изменения:
1. Случайная CV вместо CV по каркасам.
2. Поиск масштабного коэффициента `c` в диапазоне [1, 8] по обрезанной MSE (99.7-й процентиль).
3. **Поправка по аналогу**: если у соединения есть очень похожий сосед в обучении, прогноз сдвигается к его SI с весом `w_max = 0.4` (или 0.6 в «сильном» варианте). Поправка автоматически отключается, если CV показывает ухудшение больше 1%.
4. Формируются три варианта submission, чтобы можно было отдельно оценить вклад поправки по аналогам.

**Публичный лидерборд после v2:** **1 536 206.96** (−125 687 ≈ 7.6%).

Улучшение скромное относительно разрыва до топ-10 (~0.7 млн). Большая часть оставшейся ошибки сосредоточена в одном-двух экстремальных значениях SI. Гипотезу про аналоги CV полностью проверить не могла, потому что в обучении нет настоящих пар эпимеров.

### Что сознательно не делалось
- Не использовались скрытые метки теста (`CC50_uM`, `IC50_uM_VACV`).
- Не применялась агрессивная калибровка, которая переобучается под несколько экстремальных выбросов.
- Не было ручного «хардкода» прогнозов для трёх «близнецов».

## 3. Финальный пайплайн

Рекомендуемое финальное решение — **v2**.

### Быстрый старт (воспроизводимый)

```bash
# 1. Окружение
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. (Опционально) Сбор / обновление внешних данных
#    Требует интернет. Кэш лежит в data/external/cache/
python -m src.collect_data \
    --out data/external/vacv_external_raw.csv \
    --doc-timeout 300 \
    --max-activities 50000

python -m src.validate_data \
    --in data/external/vacv_external_raw.csv \
    --out data/external/vacv_external_clean.csv

# 3. Обучение v2 (финальная модель)
python -m src.train_v2 \
    --out outputs_v2 \
    --external data/external/vacv_external_clean.csv

# 4. Файл для Kaggle
#    Загружать: outputs_v2/submission.csv
```

Если у вас уже есть заполненный `data/external/cache/` и чистый CSV, шаг сбора можно пропустить.

### Офлайн / запасной режим
```bash
bash run_all.sh --offline
# или
python -m src.train --fallback-no-rdkit
```
Создаёт `submission_fallback_noRDKit.csv` (более слабые признаки, нужен только для проверки формата).

### Чек-лист воспроизводимости
- Все случайные сиды зафиксированы в `src/utils.py`.
- Два подряд запуска одной и той же команды дают побайтово одинаковый `submission.csv` (проверено в fallback-режиме).
- Молекулы из тестового набора по умолчанию удаляются из внешних данных.
- Юнит-тесты защищают от случайного использования меток теста.

## 4. Сформированная база данных

Чистая внешняя база находится в файле:

```
data/external/vacv_external_clean.csv
```

Обязательные столбцы (в точности по требованиям):

| Столбец  | Описание                                      |
|----------|-----------------------------------------------|
| SMILES   | Каноническая SMILES-запись соединения         |
| IC50     | Полумаксимальная ингибирующая концентрация    |
| CC50     | 50%-ная цитотоксическая концентрация          |
| SI       | Индекс селективности = CC50 / IC50            |
| DOI      | DOI научной публикации (при наличии)          |

Дополнительные столбцы (ID документа, тип ассая, клеточная линия, штамм и т.д.) могут присутствовать, но не являются обязательными.

Источники:
- **ChEMBL** (основной) — типы активностей IC50 / EC50 / CC50 / … против Vaccinia / ортопоксвирусов.
- **PubChem** (дополнительный / экспериментальный).
- Ручные дополнения из статей (шаблон есть в коллекторе).

## 5. Как воспроизвести результат с Kaggle

1. Использовать тот же снимок внешних данных, который был при генерации submission (папка `data/external/`, особенно кэш).
2. Запустить `python -m src.train_v2 --out outputs_v2 ...` с теми же флагами.
3. Загрузить `outputs_v2/submission.csv`.

Поскольку публичный лидерборд сильно зависит от нескольких экстремальных значений SI, небольшие различия в поправке по аналогам или глобальном масштабе могут менять балл на десятки или сотни тысяч. Порядок величины (≈ 1.5 млн) стабилен.

## 6. Замечания к защите

- Главная сложность моделирования — экстремальный перекос целевой переменной. Классическая MSE почти бесполезна; необходимы обрезанная MSE и аккуратная работа со структурными аналогами.
- Хиральность / эпимеры невидимы для используемых отпечатков. Возможное улучшение в будущем — хиральные отпечатки или 3D-дескрипторы.
- Поправка по аналогам — гипотеза, основанная на наблюдении трёх почти идентичных пар между train и test. Она не гарантирована и контролировалась через CV (`w_max` обнуляется при ухудшении).
- Все пути, которые могли бы привести к утечке меток теста, защищены юнит-тестами.
